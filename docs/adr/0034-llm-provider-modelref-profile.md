# LLM Provider, ModelRef, Profile, and unified bind map

Extends [0006](./0006-llm-provider-port.md) and the per-node bind reserved in [0022](./0022-complete-only-llm-port.md). Modules keep depending only on `LlmPort` via `get_llm_port(node)`; `get_research_llm` / `get_spec_llm` go away. Composition root binds one port per Workflow Node from a repo map of node → **Profile** name, with optional env overrides.

**Provider** is a named credential endpoint (`id`, `kind`, `base_url`, timeouts, `api_key_env` — secrets stay in separate env vars, not JSON). **ModelRef** is `provider_id` + vendor model id. **Profile** is a named alias to exactly one ModelRef (no call knobs). Day-one kinds: `langchain` (OpenAI-compatible, including FIT@HCMUS) and `fake`. Day-one profile names `creative`, `research`, `structured`, and `judge` may share one ModelRef. Live profiles must implement `complete_structured`. Runtime fake uses generic `FakeLlm`; research/spec domain fakes stay test-only injects. Account UI does not choose models. Anthropic/Google SDKs wait until a concrete vendor is required. These terms are composition infra, not `CONTEXT.md` language.

Env carries JSON `LLM_PROVIDERS` and `LLM_PROFILES` (and optional `LLM_NODE_PROFILE_OVERRIDES`). Empty JSON uses built-in defaults: Provider `ai-fit` (`kind=langchain`, `LLM_API_KEY` / `LLM_BASE_URL`) plus `fake`, and all four Profiles → ModelRef(`ai-fit`, `LLM_DEFAULT_MODEL` default `Qwen3.6-27B`). Fake for local/tests is opt-in via JSON or test injects — not a parallel `RESEARCH_LLM_*` factory. Migration: Profiles JSON that still reference `provider_id` `openai` must declare that Provider in `LLM_PROVIDERS` or retarget to `ai-fit`. Default node map in repo: grilling nodes → `creative`; `research_inputs` / `related_work` / `gap` → `research`; contribution through feasibility → `structured`; judge nodes and `aggregator` → `judge`.

**Considered options:** flat per-node LangChain instances with only `LLM_*`; keep research on a parallel `RESEARCH_LLM_*` factory; Profile as provider+model+knobs without ModelRef; secrets embedded in provider JSON; Account-selectable models; default Provider id `openai` / `fit`; dual `fit_webui` kind beside `langchain`.

**Why:** TOPIC and ADR 0006 already allow different LLMs per Workflow Node; a single bind map removes the research/spec split without putting vendor config in `loop.catalog`. Provider / ModelRef / Profile keeps credentials, model ids, and role aliases independent so ops can retarget profiles without rewriting the node map. Campus FIT is the zero-config default because that is the live endpoint this repo targets; OpenAI-compatible `langchain` still covers additional endpoints without new SDKs. Dropping `RESEARCH_LLM_*` and the `openai` default id avoids a second naming scheme that drifted from the JSON map.
