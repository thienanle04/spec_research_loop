# Stale re-accept gate, Node Head generate flag, and Stale visibility

Confirming a Stale Workflow Node after `recompute-prepare` without a successful post-prepare generate or Judge Run requires an explicit **Stale re-accept** ack on the Confirm request. The loop API rejects Confirm when the Node Head is Stale, `generated_since_prepare` is false, and the ack is missing. A boolean (or equivalent) on the Node Head clears when the head becomes Stale and when prepare runs, and sets when generate or Judge Run succeeds on that node. The ack is request metadata only — not a Decision; hash-matching Confirm still clears Stale without minting a revision (ADR 0010 / confirm path unchanged aside from the gate).

UI: stronger Stale treatment on the stage path; after an invalidation wave, a dismissible banner shows Stale only for the **currently viewed** Workflow Node plus Spec Draft when there is no Valid Spec Version — not a full inventory. Dismiss is per subject (each Workflow Node and Spec Draft separately) for the current wave; other Stale subjects still alert when opened. A new invalidation wave clears dismissals. Dim Stale head revision and post-prepare Working Draft only while that banner is showing **and** Stale re-accept is still needed (Dismiss undims; post-prepare generate or Stale re-accept also undims; refresh restores banner and dim). Confirm opens a dialog (Generate runs immediately, or Confirm anyway). Dismiss does not skip the Confirm gate.

**Considered options:** UI-only warning (rejected — Accidental Confirm still hits the API); block Confirm until generate (rejected — intentional keep-old-content must remain); client-only “generated since prepare” (rejected — refresh bypass); always-ack even after generate (extra friction); banner listing every Stale node (rejected — noise; path + contextual banner suffice); wave-scoped Dismiss that silences every Stale subject (rejected — navigating to another Stale node looked like a missing alert); dim until generate/re-accept even after Dismiss (rejected — Dismiss should acknowledge and restore full-opacity editing).

**Why:** Prepare restores the last Stage Revision while the head stays Stale, so Confirm can succeed with upstream-skewed content and little feedback. Server-side gate + Node Head flag make Stale re-accept deliberate; path/banner cues plus dim-while-banner-visible make Stale obvious without autopilot generate (ADR 0033).
