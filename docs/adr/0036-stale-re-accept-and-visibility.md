# Stale re-accept gate, Node Head generate flag, and Stale visibility

Confirming a Stale Workflow Node after `recompute-prepare` without a successful post-prepare generate or Judge Run requires an explicit **Stale re-accept** ack on the Confirm request. The loop API rejects Confirm when the Node Head is Stale, `generated_since_prepare` is false, and the ack is missing. A boolean (or equivalent) on the Node Head clears when the head becomes Stale and when prepare runs, and sets when generate or Judge Run succeeds on that node. The ack is request metadata only — not a Decision; hash-matching Confirm still clears Stale without minting a revision (ADR 0010 / confirm path unchanged aside from the gate).

UI: stronger Stale treatment on the stage path. After an invalidation wave, a non-dismissible banner shows Stale only for the **currently viewed** Workflow Node while Stale re-accept is still needed, plus Spec Draft when there is no Valid Spec Version — not a full inventory. Successful post-prepare generate hides the node line (the Node Head flag, including when browsing the Stale Stage Revision). Spec Draft’s line keeps the same in-view rules and stays until a Valid Spec Version exists. Working Draft and Stage Revision stay full opacity. Independent judges still has no Aggregator node line (ADR 0040). Confirm opens a dialog (Generate runs immediately, or Confirm anyway). The Confirm gate is unchanged.

**Considered options:** UI-only warning (rejected — Accidental Confirm still hits the API); block Confirm until generate (rejected — intentional keep-old-content must remain); client-only “generated since prepare” (rejected — refresh bypass); always-ack even after generate (extra friction); banner listing every Stale node (rejected — noise; path + contextual banner suffice); dismissible banner plus dim-while-banner-visible (reversed — dim existed so Dismiss could restore full-opacity editing; a persistent gate-cue banner makes dim redundant, and Dismiss hid a still-true warning); Spec Draft line only on Spec Draft / Independent judges (rejected — keep today’s in-view rules).

**Why:** Prepare restores the last Stage Revision while the head stays Stale, so Confirm can succeed with upstream-skewed content and little feedback. Server-side gate + Node Head flag make Stale re-accept deliberate; path plus a current-view banner (only while the ack is still needed) make Stale obvious without autopilot generate (ADR 0033) and without dimming editable content.
