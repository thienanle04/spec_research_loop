# Independent judges dashboard, Judge Confirm off Working Draft, Aggregator generate when five heads are current

Independent judges stays six Workflow Nodes (ADR 0014, 0039). The Account-facing stage is one dashboard: compact Judge Node Heads plus the Aggregator Report (Issues, Handling Options, PICK). `recompute-prepare` still resets empty or Stale nodes in the stage but always lands Working Draft on Aggregator, including when Aggregator is empty or Stale (exception to ADR 0016’s `first_needs_work`). Successful generate on a Judge records Confirm of that Judge even when Working Draft is Aggregator (exception to ADR 0017); failed or aborted generate does not. Opening the stage still does not generate Judges (ADR 0033). “Run pending Judges” remains an Account action and still does not start Aggregator. When all five Judge heads are current, Aggregator generate starts and may carry Stale re-accept for Aggregator; that ack does not cover Confirm Aggregator (narrow exception to ADR 0036 / the run-pending ack scope in ADR 0039). Confirm Aggregator still requires Working Draft Aggregator, freezes even with CRITICAL Issues, and continues to Readiness. PICK still requires working Aggregator Report and still reopens the target Workflow Node.

**Considered options:** merge five Judges into one Workflow Node (rejected — invalidation and independent Prompt Views); skip freeze and let Aggregator read Working Draft Judge Runs (rejected — Node Heads never current); auto-generate Judges on open (rejected — ADR 0033); auto-Confirm Aggregator (rejected — PICK is on the working report; Readiness needs an Account Confirm); keep per-Judge Confirm and six destinations (rejected — Account cannot edit Judge Issues, so Confirm was only freeze friction).

**Why:** Judges stay independent snapshots; the Account’s remaining judgement Decisions are run-pending, PICK, and Confirm Aggregator.
